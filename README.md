# MBDP: Multivariate Bayesian Directional Predictor

Code accompanying **MBDP: A Rolling Multivariate Bayesian Generative Framework for Market Direction Prediction**.

MBDP combines a causal, uncertainty-normalized return state with local class-conditional estimation, smoothed priors and likelihood-based scoring for risk-adjusted trading. The main evaluation concerns trading decisions; a matched CNNPred assessment provides complementary directional and probability diagnostics.

We retain the name Multivariate Bayesian Directional Predictor (MBDP); the present study evaluates its one-dimensional specialization for each asset.

## Quick start

The trading comparison is implemented entirely in `Code.py`. It uses the two bundled market CSV files and requires no GPU or data downloads. Python 3.13 was used for verification.

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python Code.py
```

Run these commands from the directory containing `Code.py`. The default execution evaluates six strategies across three market panels at transaction fees of 5, 10 and 20 basis points per leg, writing **54 rows to `results.csv`**. Numba compiles the numerical loops on the first run.

## Model and execution

The pipeline is:

```text
Closing prices → causal return state → uncertainty normalization
               → local class estimation → model-based probability scores
               → signed utility decisions → fixed-unit positions → net metrics
```

For each asset, the model represents local return location relative to predictive uncertainty as a scalar state, $x=\mu/\sigma$. Class means, regularized scales and smoothed priors are estimated from completed historical observations. The reference specification uses pooled Gaussian class scales with ridge `1e-6` and the component-orientation rule specified in the paper.

At each monthly boundary, the discount parameter beta and risk penalty gamma are jointly selected from completed historical utility replay. Their selected values and the class fit are held fixed for the next forward block, while the recursive state continues updating as observations arrive.

| Setting | Value |
| --- | --- |
| Historical selection window | Trailing 12 calendar months; truncated to available history near the initial DRL-Ensemble boundary |
| Forward step | One calendar month |
| Beta candidates | `0.80, 0.85, 0.90, 0.95, 1.00` |
| Gamma candidates | `0.0000, 0.0025, ..., 0.9975` |
| Candidate pairs | 2,000 per active strategy, boundary and fee |
| Selection criterion | Historical net terminal utility-replay return, including fees and liquidation |
| Tie rule | First maximum in ascending beta, then gamma order |
| Within-block decision interval | `H = 30` observed bars, restarting at each monthly boundary |
| Default transaction fees | 5, 10 and 20 basis points per leg |

The first eligible observation in each monthly block is a decision opportunity. A review can preserve the existing position without creating a transaction. Historical parameter replay counts 30-bar opportunities from its trailing-window origin, without interior monthly resets; forward execution restarts the counter at each monthly boundary.

Beta controls uncertainty discounting. For constant beta below one, the limiting degree count is $1/(1-\beta)$; it is not a literal lookback length or a fixed moving-average window. Beta one retains accumulating evidence.

The active strategy can hold one long position, one short position or cash. Signed utilities combine the return score and risk scale; MBDP entry gates use the corresponding model-based probability boundaries. Each entry uses 1x notional and fixed units until the next transaction. Short-sale proceeds remain in cash. Fees are charged on entry, exit and terminal liquidation, and daily wealth is independently reconstructed from a price-and-unit ledger.

The reference MBDP runs executed no short entries, although the implementation supports them. Borrow/funding charges, dividend reimbursement, slippage and broker margin rules are not separately modeled.

## Independent baselines

The script runs:

- MBDP;
- equal-weight buy-and-hold;
- logistic regression;
- shrinkage LDA;
- random forest;
- 20-return momentum.

Each active baseline trades its own scores and selects its own beta and gamma on the same historical grid. Classifiers have separate causal state histories and monthly fits for every beta candidate. All active methods share the panel dates, decision schedule, fixed-unit accounting and per-leg fee convention. Buy-and-hold is a long-only passive reference.

Logistic regression uses `C=1`, `lbfgs` and `max_iter=200`. LDA uses `lsqr` with automatic shrinkage. Random forest uses 100 trees, maximum depth 3, minimum leaf size 10 and seed 42. Classifier probabilities are converted to trading scores through `sigma * logit(p)`, with probabilities clipped to `[1e-6, 1 - 1e-6]`; this is a score-to-trade convention. Momentum uses a causal 20-log-return mean, with beta changing its risk scale.

| Script panel name | Manuscript setting | History begins | Test begins | Inclusive endpoint |

These are calendar slicing boundaries; actual observations follow each file's available dates. Equity inputs use `Date`, `Ticker` and `Adj Close`; Bitcoin inputs use `date` and `close`. Asset eligibility is determined from valid positive pretest prices. Annualization uses 252 observed bars for equities and 365.25 for Bitcoin.

## Output and options

`results.csv` contains one row per panel, method and fee. Canonical columns include `total_return`, `cagr`, `sharpe`, `volatility`, `mdd`, `turnover`, `trades` and `exposure`. Returns, volatility and exposure are fractions; explicit `*_pct` columns provide percentages. `mdd` and `max_drawdown_pct` are positive loss magnitudes, while the paper prints signed drawdown. `trades` counts filled transaction legs.

Active-strategy rows additionally report long, short and cash days, entry counts, and the maximum ledger reconstruction error. The JSON manifest records settings, package versions, source/data hashes and any requested reference check. Results are saved after each completed run; rerunning replaces the specified output files.

```bash
# Use one worker instead of parallel beta fitting.
python Code.py --workers 1

# Save daily wealth, trades, monthly selections and fitting endpoints.
python Code.py --audit-dir audit

# Run only Bitcoin at 20 basis points per leg.
python Code.py --markets BTCUSD_Daily --fees-bps 20 --output btc_results.csv

# Include the zero-fee case.
python Code.py --fees-bps 0 5 10 20 --output costs_results.csv

python Code.py --help
```

Default data and output paths are relative to `Code.py`; `--data-dir` and `--output` override them. Up to five workers fit beta candidates in parallel by default. If a reference CSV is available, `--verify-against path/to/reference.csv` compares freshly recomputed metrics against it after execution. A full run of the supplied script was checked against all 54 synchronized manuscript rows.

## Other experiments in the paper

`Code.py` reproduces the synchronized financial comparison. Published RL/hybrid rows in the comparative table retain their source-study context and are distinct from these executable controls.

The matched CNNPred task evaluates MBDP and CNNPred on the same daily targets and reports accuracy, macro-F1, Brier score, ECE, Pesaran–Timmermann tests and reliability diagrams. Its MBDP historical replay interval is one bar, separately from the main trading schedule. The preliminary CNNPred, DANSMP and SAMBA extensions retain their contextual role in the appendix.

`Manuscript/Supplementary_Experiments.zip` contains the separate experimental drivers, diagnostics and table/figure generation scripts. It is not required by the standalone financial script.
